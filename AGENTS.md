# AGENTS.md — Ravocal

## Project Overview

Ravocal is a group scheduling and ranked-choice voting app. Users create groups, invite members via email, and each member marks blocks of time they are free. The group owner starts a ranked-choice vote over overlapping free slots; members vote, and the winning slot is displayed in-app. If no slots meet the group's overlap threshold, the owner can force a vote that prioritizes their own availability while maximizing overlap for the group.

Monorepo: npm workspaces with three packages: `app/` (`@cubicecho/ravocal-app`, frontend), `server/` (`@cubicecho/ravocal-server`, GraphQL API), and `db/` (`@cubicecho/ravocal-db`, database schema and connection).

The repo follows the cubicecho skills (`cubicecho_typescript`, `cubicecho_backend`, `coding-standards`) for everything not written here.

## Domain Model

### Entities

- **User** — identified by email; signs in via magic link (or, under `SECURE_LOCAL_NET`, by typing the address), or with Google, Facebook or the instance's OIDC provider when it offers them. No passwords. One user is the instance's **admin** (`is_admin`): the first account made, who may change how people sign in.
- **Group** — has one owner (creator), a name, and a configurable overlap threshold (0–100%). Owner is the only one who can start/force votes and manage membership.
- **GroupMember** — join table linking users to groups.
- **GroupInvite** — an invite link (tokenized), emailed to an address but not tied to it: whoever opens it while signed in joins, once, before it expires. The owner can cancel it.
- **TimeBlock** — a contiguous free-time window (30-min aligned start/end) that a group member submits to the group's shared calendar.
- **Vote** — created by the group owner. Status: `pending → active → closed`. Can be `isForced = true` if the owner bypassed the overlap threshold.
- **VoteSlot** — a candidate time slot attached to a vote (derived from overlapping TimeBlocks, or forced from owner's blocks), with its ballot `position`.
- **VoteRanking** — a member's ranked-choice ranking of VoteSlots (rank 1 = top choice).

### Overlap threshold

Each group stores an `overlapThreshold` (integer 0–100, default 50). A normal vote is only allowed when at least that percentage of members have marked a common slot as free. Below the threshold the owner can start a forced vote; in forced mode, slots are ranked by: (1) owner is free, (2) most members free.

### Email notifications

Three events trigger email: group invite, vote started, vote result announced.

## Build / Dev / Lint / Test Commands

All commands run from the **project root**.

### Development

```bash
cp .env.example .env     # Once. DATABASE_URL points at the dev Postgres
npm run db:up            # Start the dev Postgres (port 5436) and Mailpit (SMTP 1036, web UI 8036)
npm run dev              # Start server + app concurrently
npm run dev:app          # Vite dev server only (port 5173)
npm run dev:server       # The API only (port 3001, watch mode)
npm run db:down          # Stop them
```

The server runs preflight (it refuses a missing `DATABASE_URL`, in production a weak `BETTER_AUTH_SECRET`, `SECURE_LOCAL_NET` with a public `APP_URL`, a Google or Facebook client id without its secret or the reverse, and half an `OIDC_ISSUER`/`OIDC_CLIENT_ID`, a non-URL issuer, in production an `http:` issuer on a public host, or an unknown `OIDC_CLIENT_AUTH`), waits for Postgres, applies the migrations in `db/drizzle`, then listens. `GET /healthz` answers `{ ok, version }`, or 503 when Postgres doesn't. SIGTERM drains and exits 0. If the Docker daemon is remote (`docker context ls`), set `DEV_BIND=0.0.0.0` and put the daemon's host in `DATABASE_URL` and `SMTP_URL`.

### Signing in during development

Sign-in links go out over `SMTP_URL`, which `.env.example` points at the Mailpit `npm run db:up` starts: request a link, then open it from http://localhost:8036 (Mailpit's web UI; `GET /api/v1/messages` for scripts). Invite and vote emails land there too. With no mail server at all, set `SECURE_LOCAL_NET=true` instead: typing an address signs straight in. With neither and no provider, nobody can sign in, and the server warns at boot; the login page of an instance with no accounts still offers to pair a provider.

Google and Facebook need real clients (`.env.example` walks through both consoles); the server prints each redirect URI to register at boot. Without them, the provider tests (`server/src/__tests__/http/sso.test.ts`) run the whole flow against a stand-in on loopback, and the pairing tests (`server/src/__tests__/sso/pairing.test.ts`) do the same for a Dynamic Client Registration provider. To try pairing by hand, run a throwaway DCR + OIDC stand-in on a port the dev server can reach and paste its setup URL on an empty database's login page.

The app talks to the API through Vite's proxy in development (`/graphql`, `/sso/`, `/api/auth/`) and from the same origin in production, so the server sends no CORS headers, and `SERVER_URL` (where a provider sends the reader back) defaults to `APP_URL` in both. Every variable is described in `.env.example`; the server reads them only through `server/src/core/config.ts`.

## Deployment

The image (`Dockerfile`) is the only deliverable. The builder stage runs `npm ci`, codegen and the Vite build; the runtime stage is `node:26-slim` with only the db and server workspaces' production dependencies, their sources without `__tests__` or `*.test.ts`, `db/drizzle` and the built `app/dist`. It runs as `USER node` and writes nothing to disk (all data is in Postgres), so it needs no volume. `CMD` is exec form so node is PID 1 and gets SIGTERM; `HEALTHCHECK` fetches `/healthz` every 2s while booting and every 30s after. Keep `.dockerignore` in step with anything new at the root that the build doesn't need.

`docker-compose.yml` is the self-host install: `ghcr.io/cubicecho/ravocal:latest` plus `postgres:17-alpine` with the `ravocal_pgdata` volume and a `pg_isready` healthcheck, the app waiting for a healthy Postgres. Postgres has no published port. Every server variable is passed through from `.env`, empty when unset, so the server's own defaults apply; only `BETTER_AUTH_SECRET` is required. It has no `build:`, so the file works on its own, downloaded beside a `.env`; to run a local build, `docker build -t ghcr.io/cubicecho/ravocal:latest .` first. Migrations run at boot, so `docker compose up` on a fresh volume is the whole install.

`docker-compose.dev.yml` (project `ravocal-dev`) is development only: Postgres on 5436 and Mailpit on 1036/8036.

## CI

`.github/workflows/ci.yml`, on push to `main` and on pull requests, Node 26 with npm caching:

- **`check`**: `npm ci`, codegen, `biome ci .`, `check:types`, `npm test`, `npm run build`.
- **`postgres`**: two `postgres:17-alpine` services. On the first, `db:migrate` from empty, `drizzle-kit check`, and `db:generate`, which must leave `db/drizzle` unchanged. On the second, `check:data-migrations` (`docs/database.md`).
- **`boot`**: builds the image with Buildx (GHA cache) and loads it as `ghcr.io/cubicecho/ravocal:latest`, then `docker compose up --pull missing --wait` (the app image is already loaded, so only Postgres is pulled) with a generated `BETTER_AUTH_SECRET`. `.github/scripts/boot-smoke.sh` checks `/healthz`, an anonymous `{ groups { id } }` answering `UNAUTHENTICATED`, `{ authConfig { magicLink } }` and `GET /` serving the app; then `docker compose stop` must leave the server's exit code 0.

Run the smoke script against any instance: `.github/scripts/boot-smoke.sh http://localhost:3001`.

## Release

`.github/workflows/release.yml` runs semantic-release (`.releaserc.json`): commit-analyzer, release notes, `CHANGELOG.md`, `@semantic-release/npm` with `npmPublish: false` (so the root `package.json` version, which `/healthz` reports, follows the release), the GitHub release, and a `chore(release): X.Y.Z [skip ci]` commit. A dry run first decides whether there is a version at all; only then does it build the image from the bumped tree and push `ghcr.io/cubicecho/ravocal` as `X.Y.Z` and `latest`, labelled with the version and the release commit (the Dockerfile labels `org.opencontainers.image.source`, which links the package to the repo).

- **Trigger:** every push to `main`, plus `workflow_dispatch` to retry by hand. The job skips the `chore(release):` commit, which GitHub also skips for `[skip ci]` and because `GITHUB_TOKEN` pushes start no workflow.
- **Secrets:** none. `GITHUB_TOKEN` does it all (`contents`, `issues`, `pull-requests` and `packages: write`). There is no Docker Hub image.
- The first release is `1.0.0`. The GHCR package must be made public once in its settings, or pulls need a login.
- Commit types decide the version: `feat` minor, `fix`/`perf` patch, `BREAKING CHANGE` major; `chore`, `docs`, `ci`, `build`, `refactor`, `test` none.

## Code Style Guidelines

### Formatting (Biome)

- **Semicolons**: always
- **Quotes**: single quotes
- **Indentation**: 2 spaces
- **Trailing commas**: all
- **Line width**: 120 characters
- **Blocks**: every `if` and loop body is braced (`useBlockStatements`)
- **Negation**: a logic check is negated with `=== false` in a positively named const; `!` is for null guards only (the `no-negation.grit` plugin)
- Vendored cubeui files (`app/src/components/ui/**`, the cubeui shells and lib helpers, `cubeui-*.css`) are excluded from Biome

### Imports

- `type` imports for type-only symbols (enforced by Biome `style/useImportType`)
- `@/` path alias within `app/` (maps to `app/src/`)
- In the server, tables and row types come from `@cubicecho/ravocal-db/schema`. Only `index.ts` imports the package root, which needs `DATABASE_URL` and connects to Postgres (`import type { DB }` from the root is fine anywhere)
- Relative imports carry the real `.ts` / `.tsx` extension

### TypeScript

- Strict mode everywhere — no implicit `any`
- Prefix unused params with `_`
- `interface` for object shapes, `type` for unions/utilities
- Infer types from Drizzle (`$inferSelect` / `$inferInsert`) — never duplicate manually

### Naming

- **Files**: `kebab-case.ts` / `kebab-case.tsx`
- **Components**: `PascalCase`
- **Variables/functions**: `camelCase`
- **Types/Interfaces**: `PascalCase`
- **DB columns**: `snake_case` in SQL, `camelCase` in Drizzle (mapped automatically)
- **GraphQL**: `camelCase` fields, `PascalCase` types, `PascalCase` + `Input` suffix for inputs

### Access (key decision)

Rows are shared by **group membership**, not owned by one user. `scope` (`graphql/tenancy.ts`) confines every generated read, update and delete to the caller's groups, on every path (root, single, nested, aggregates; a client `OR` can only narrow it). It can't tell a read from a write, so graphql-casl (`graphql/permissions.ts`) narrows the generated single-row writes further by ANDing the caller's conditions into their `where`. `Mutation` is an allow-list: a write a new table generates arrives refused, and so does every bulk form. better-auth's operations are on it.

| Table                 | Read                                                 | Write                                                                                                                                                                                                                                                                                     |
| --------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `groups`              | members                                              | `createGroup` (hand-written: the group and the owner's membership in one transaction). `updateGroup` (name, threshold) and `deleteGroup`, generated, owner only (casl on `ownerId`; `ownerId` itself is never in the input)                                                               |
| `group_members`       | members of the same group                            | Hand-written only: `createGroup`, `acceptGroupInvite`, `removeMember` (owner only; not themselves; takes their time blocks in the group and their ballot in its open vote, keeps a closed vote's result)                                                                                  |
| `group_invites`       | the group's owner only; `token` is not in the schema | Hand-written only: `inviteToGroup`, `acceptGroupInvite`, `cancelInvite` (owner only; the link stops working)                                                                                                                                                                              |
| `time_blocks`         | members of the same group                            | Generated `createTimeBlock`, `updateTimeBlock`, `deleteTimeBlock`. `userId` is stamped (`contextValues`); a hook refuses a group the caller isn't in (also moving a block into one), the 30-minute grid in UTC, and an end not after the start; casl limits update and delete to your own |
| `votes`, `vote_slots` | members                                              | Hand-written only: `startVote`, `forceStartVote` (owner only; one open vote per group), `closeVote` (owner only)                                                                                                                                                                          |
| `vote_rankings`       | your own only, in a group you are in                 | Hand-written `submitRankings` (members, open votes, the vote's own slots)                                                                                                                                                                                                                 |
| `users`               | yourself, and anyone you share a group with          | `updateUser`, generated, your own row only (casl on `id`), the name only                                                                                                                                                                                                                  |

`sessions`, `accounts` and `verifications` (`AUTH_TABLES`), and `oidc_settings` (`SERVER_TABLES`, it holds the paired client's secret and registration token), are excluded from the schema. `users.is_admin` is readable like the other columns and never writable (the users hook). The client reads its own user through better-auth's `getSession`; there is no hand-written `me`.

**NOT_FOUND, never FORBIDDEN, for a row you can't reach.** (Changing the instance's sign-in is not a row: `pairSso` and `unpairSso` refuse with `FORBIDDEN` and a sentence.) A group you aren't in, a member's block you didn't make, an owner-only action you aren't the owner for, and an id that never existed all answer `NOT_FOUND`, so callers can't probe for other ids. A non-member's `group(where: …)` is `null`. A generated single-row update or delete that `scope` or casl filtered to nothing throws `NOT_FOUND` (`graphql/build-schema.ts`). `FORBIDDEN` is only a role refusal: a mutation off the allow-list, or pairing without being allowed to.

Hand-written resolvers don't inherit `scope`: they load their group through `groups/access.ts` (`loadMemberGroup`, `loadOwnedGroup`), which refuse with NOT_FOUND, and read their result back through the generated query (`graphql/read-back.ts`), so it is scoped like any other read.

### Auth

- better-auth (`server/src/auth/`), following the `cubicecho_backend` skill's auth.md: sessions in Postgres (`sessions`, `accounts`, `verifications`, uuid ids), sent as `Authorization: Bearer <token>`, signed with `BETTER_AUTH_SECRET`
- Its endpoints are served as GraphQL by `@cubicecho/graphql-better-auth`, limited to `BETTER_AUTH_OPERATIONS` (`signInMagicLink`, `magicLinkVerify`, `verifyOneTimeToken`, `getSession`, `listSessions`, `signOut`, `revokeSession`, `revokeSessions`, `revokeOtherSessions`, `linkSocialAccount`, `listUserAccounts`, `unlinkAccount`). Its REST routes are not mounted, except a provider's callback (`http/sso.ts`). `authConfig { secureLocalNet magicLink providers { id name signInUrl } }` tells the login page what is on offer
- `createApp({ db, authHost })` takes an `AuthHost`, and each request's context carries `ctx.auth` (`authHost.current()`) and `ctx.authHost`. No module imports a global auth; tests build a real one on PGlite (`createTestAuth`) and wrap it in `fixedAuthHost(auth, providers)`
- Google, Facebook and the OIDC provider (`auth/providers.ts`, id `oidc`) run through better-auth's `genericOAuth`; Google's and Facebook's endpoints are an argument of `createAuth` (tests only, never the environment), and the OIDC provider is found by its issuer's discovery document. A provider's sign-in ends on the app's `/auth/sso` with a one-time token that `verifyOneTimeToken` swaps for the bearer session; the session never rides in a URL or becomes a cookie
- **Linking by address (key decision):** no provider is trusted by name. A provider sign-in reaches the account that has its address only when the provider says it checked the address: Google's and the OIDC provider's `email_verified` claim, passed through as-is (missing counts as unchecked); Facebook never says so. One rule whichever providers are set up (`requireLocalEmailVerified: false` always). So a Google-checked address signs in to the account that has it, even an unconfirmed `SECURE_LOCAL_NET` one, and an unchecked Google address or any Facebook one that an account already has is refused as `account_not_linked` (the reader signs in by email and connects the provider in Settings). A new address makes an account whose address is unconfirmed; no address is `email_not_found`. Connecting a provider in Settings (`linkSocialAccount`) links it to the signed-in reader whatever its address. Disconnecting the last way to sign in is refused unless an email link would still reach the reader
- **First proof of an address (key decision):** when an unconfirmed account's address is first proven (a magic link, or a Google or OIDC sign-in its provider checked; never `SECURE_LOCAL_NET`), its sessions end and every provider account but the one proving it is deleted (`auth/unproven-access.ts`, better-auth database hooks; the magic link also does it itself). So an account made by someone who did not own the address keeps no way in. Providers connected from Settings after the proof are kept, since an address is proven only once. Group memberships the account gained before the proof are kept
- **The OIDC provider: where it comes from (key decision).** Only `sso/settings.ts` `effectiveOidc(db)` decides: `OIDC_ISSUER` plus `OIDC_CLIENT_ID` in the environment **wins**, and the app cannot change it; otherwise the `oidc_settings` row a pairing wrote; otherwise none. Pairing pastes a setup URL, `<issuer>#setup=<initial access token>&name=<label>`: Ravocal checks the discovery document names that issuer **before the token is sent anywhere**, registers itself (RFC 7591) and keeps the client; `pairSso`/`unpairSso` then `authHost.rebuild()`, so the button appears or goes without a restart. **The setup token is never stored or logged**, and rides in the fragment so no server logs it either. Unpairing deletes the client at the provider (RFC 7592) and forgets the row whatever it answers
- **Who may pair (key decision):** nobody when the environment sets the provider; the admin; or anyone while the instance has no accounts at all, so whoever installs it can set sign-in up from the login page. Once anyone has an account, a stranger's provider could vouch for an existing address, so only the admin may. **The admin** is the first account made (`auth/admin.ts`, better-auth's `user.create.after`, one statement, at most one admin by `uq_users_one_admin`); the `oidc_pairing` migration made the oldest account the admin on an instance that already had accounts
- Every sign-in step calls `throttle(ctx, flow, email?)` first, and so do `pairSso` and `unpairSso`: `ctx.limiter`, keyed by client address and by email, refused as `TOO_MANY_REQUESTS`. `ctx.ip` is only the client's when `TRUST_PROXY` matches the proxies in front
- A spent, expired or unknown link is `BAD_USER_INPUT`, never `UNAUTHENTICATED`: the app drops its token on `UNAUTHENTICATED`, and a bad link must not sign anyone out

### Error handling

- Yoga masks every error that isn't a `GraphQLError` as `Unexpected error.`, so a failure the client should read is thrown with a coded helper from `server/src/core/errors.ts`. The app branches on the code (`app/src/lib/error-codes.ts`) and shows the message
- Input is parsed with `parseOrThrow(schema, value)` (`core/validation.ts`), and every zod rule carries a sentence
- Read a caught value with `errorMessage(error)`, never `(error as Error).message`
- Never swallow errors silently
- Always surface errors to the user or log them
- Log lines carry a `[subsystem]` tag: `[server]`, `[db]`, `[auth]`, `[graphql]`, `[preflight]`, `[email]`. Sign-in links and tokens are never logged
- Emails a write announces (an invite, a vote opening or closing) are sent once it has committed, through `ctx.mailer`; a failed send is logged, not thrown. A side effect from an `onWrite` hook goes through `onCommit`

### Tunables

- Every limit, lifetime, size and timeout is a member of a `<CONCEPT>_DEFAULTS` group in `server/src/core/defaults.ts` (`DATABASE_DEFAULTS` is in the db package), and tests read the group rather than repeat its numbers

### Testing

- Test files in `__tests__/` or as `*.test.ts`. The app's pure helpers are tested beside them (`app/src/lib/*.test.ts`, the `app` Vitest project, a fork per file so a test can move `TZ`)
- Database tests run on in-memory PGlite: `createTestDb()` in `beforeAll`, `resetTestDb(db)` in `beforeEach`, `closeTestDb(db)` in `afterAll` (`server/src/__tests__/helpers.ts`)
- `vitest.config.ts` sets `DATABASE_URL` empty, so a test that imports the db package root fails instead of touching a real Postgres, and empties `SMTP_URL` and `SECURE_LOCAL_NET`
- Sign-in is tested with real better-auth: `createTestAuth(db)` captures links in `links`, `createSessionToken(auth, userId)` starts a session, and `createClient(db, userId, { auth, authHost, limiter, ip, headers, mail })` shares them; `mail` collects what the mailer sent. Google and Facebook are tested over HTTP against a stand-in provider on loopback (`__tests__/http/fixtures/fake-provider.ts`, whose OpenID half is `oidc-issuer.ts`), and pairing against a Dynamic Client Registration stand-in (`__tests__/sso/fixtures/fake-dcr.ts`), never a mock
- `describe` / `it` / `expect` from Vitest (globals enabled)
- HTTP-level behaviour (masking, operation limits, the body cap, `/healthz`, the SPA, CORS) is tested against the real `createApp` in `server/src/__tests__/http/app.test.ts`; in-process `graphql()` skips Yoga
- The access rules are tested table by table in `__tests__/graphql/access.test.ts`, and `__tests__/graphql/tenancy.test.ts` fails when an exposed table has no `scope`, a hidden table is reachable, a generated write the map doesn't name is allowed, or a served better-auth operation, `ssoSetup`, `pairSso` or `unpairSso` is denied
- Fresh test context in `beforeEach`
